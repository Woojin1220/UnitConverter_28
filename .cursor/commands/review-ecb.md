# Review ECB — 아키텍처·계약 위반 점검

**코드 수정 금지.** `src/`, `tests/`, `UnitConverter.py`를 읽고 분석만 한다. 위반 수정은 사용자가 별도 요청할 때까지 하지 않는다.

## 필수 선언

응답 **첫 줄**:

```
Mode: REVIEW | Scope: ECB·계약 | 수정: 없음
```

## 점검 범위

`.cursorrules` 기준으로 아래만 검사한다:

| 카테고리 | 검사 항목 |
|----------|-----------|
| **ECB import** | `entity` → 상위 import 없음 / `control` → `entity`만 / `boundary` → `control`만, `entity` 직접 호출 없음 |
| **책임·배치** | 도메인 로직이 `src/entity`에만 / `UnitConverter.py`는 thin wrapper / SRP(검증·변환·출력 분리) |
| **입출력 계약** | 입력 `단위:값` / 출력 `{값} {단위} = {변환값} {대상단위}` / 입력 단위 출력 제외 |
| **거부 계약** | 음수·콜론 없음·잘못된 형식·미등록 단위 처리 |
| **도메인 계약** | 변환 비율 meter 기준 (`1m = 3.28084ft`, `1m = 1.09361yd`) |
| **테스트 ECB** | `tests/entity`·`tests/control`이 boundary 우회 import 없음 / 파일명·위치 `test_d_*`·`test_u_*` |

TDD Phase·Mock·pytest 통과 여부는 **본 Command 범위 밖**.

## 절차

1. **대상 파악** — 사용자가 지정한 파일·Layer 없으면 `src/**`, `tests/**`, `UnitConverter.py` 전체 스캔.
2. **import 추적** — 각 Layer 파일의 `import`·호출 관계를 ECB 방향과 대조.
3. **계약 대조** — 입출력·거부·비율·wrapper 여부를 코드·테스트 assert와 대조.
4. **위반만 기록** — 준수 항목은 생략. 위반·의심만 표에 적는다.
5. **보고** — 아래 표 형식으로만 출력. 수정 제안은 "권고" 열에 한 줄, **코드 패치 금지**.

## 보고 형식 (표)

위반이 없으면:

| 결과 | 요약 |
|------|------|
| PASS | ECB·계약 위반 없음 |

위반이 있으면 행을 추가한다:

| # | 카테고리 | 위반 | 파일:줄 | 근거 (Rule) | 권고 |
|---|----------|------|---------|-------------|------|
| 1 | ECB import | `entity`가 `control` import | `src/entity/foo.py:3` | boundary→control→entity | import 제거, 의존 역전 |
| 2 | 입출력 계약 | 입력 단위가 출력에 포함됨 | `src/boundary/cli.py:42` | 입력 단위 출력 제외 | 필터 로직을 boundary에 유지 |

- **위반** — 무엇이 규칙과 다른지 한 줄.
- **파일:줄** — 확인 가능한 위치. 불명확하면 `파일`만.
- **근거** — `.cursorrules` 해당 조항 키워드.
- **권고** — 수정 방향 한 줄 (구현·패치는 하지 않음).

## 금지

- 어떤 파일도 **생성·수정·삭제**하지 않음
- 위반을 "일단 통과"시키기 위한 **리팩터·테스트 변경 제안을 실행**
- ECB·계약 외 항목(스타일, 성능, 네이밍 취향) 장황한 리뷰
- 위반 없을 때 표를 채우기 위한 **의심 나열**

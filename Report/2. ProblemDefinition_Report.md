# Problem Definition Report

**프로젝트:** Unit Converter  
**작성일:** 2026-06-05  
**방법:** Rob Fitzpatrick Mom Test 인터뷰

---

## 1. 페르소나

코딩 수업·과제에서 **주어진 단위와 값**을 **다른 모든 단위**로 바꿔야 하는 학습자.

- 공식·변환 비율을 **외우지 않음**
- **새 단위 조합**이 나올 때마다 방법을 **다시 찾아봐야** 함
- 교수님 지시·과제 제출 맥락에서 **즉시 답하기 어려움**

---

## 2. 진짜 문제 (한 문장)

> **외울 수 없는 다양한 단위 조합 앞에서, 매번 찾아보느라 바로 답하지 못하고 과제가 지연된다.**

| Mom Test 축 | 내용 |
|-------------|------|
| **불편** | 새 단위마다 다시 찾아봐야 함, yard→ft 등 헷갈림 |
| **비용** | 과제 지연 |
| **판정** | 교수님께 즉시 답하기 어려움, "다른 단위도 숙지하라"는 피드백 |
| **재현** | ft→m 때부터 동일한 패턴, 단위 종류가 많아 미리 대비 불가 |

---

## 3. Mom Test 증거 (답변 인용)

1. "공식을 사실 왜우고 다니지는 않아서, ft에서 m로 유닛을 바꾸는 방법을 **찾아서** 바꿨어"
2. "새로운 단위를 물어볼때마다 **찾아봐야한다는 점이 불편**했어"
3. "**과제지연**"

---

## 4. 표면 문제 (잘못된 정의)

> "주어진 값을 원하는 유닛 단위로 바꿔주는 **프로그램을 만든다**."

솔루션(앱·프로그램)부터 정의하면, 실제 불편과 검증 가능한 문제가 가려진다.

---

## 5. 주제 한 문장 (Mom Test 기반, 솔루션 최소화)

> **앞으로 어떤 단위 조합이 나올지 모르는 과제에서, 매번 검색·재확인 없이 변환 결과를 바로 얻어 제출 흐름이 끊기지 않게 한다.**

Pain(검색 반복·지연) 중심. "프로그램을 만든다"는 표현은 목표가 아니다.

---

## 6. R-G-I-O

| | 내용 |
|---|------|
| **Role** | 단위 변환 담당자 — 코딩 과제에서 `단위:값` 하나를 받아 **나머지 모든 단위**로 바꿔야 하는 사람 |
| **Goal** | **한 번의 입력**으로 지원 단위 전체에 대한 **정확한 변환 결과**를 즉시 확인하고, 과제에 바로 쓸 수 있는 상태로 만든다 |
| **Input** | `단위:값` 문자열 (예: `meter:2.5`). 지원 단위: meter, feet, yard (세션 후반: 동적 등록·설정 파일) |
| **Output** | 입력 단위를 제외한 **모든 지원 단위**에 대한 변환 결과 (예: `2.5 meter = 8.2 feet`, `2.5 meter = 2.7 yard`, …) |

---

## 7. 성공 기준 3개 (Mom Test 증거와 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| **SC1** | `meter:2.5` 입력 **한 번**으로 feet·yard 등 **전 단위 변환 결과가 즉시** 출력된다 (별도 검색·수기 계산 불필요) | ① "방법을 **찾아서** 바꿨어" → **찾기 비용 제거** |
| **SC2** | **새 단위**가 추가돼도 기존 변환 로직을 거의 건드리지 않고, **같은 방식으로** 전체 단위 변환이 동작한다 | ② "새 단위마다 **찾아봐야** 불편" → **반복 탐색·헷갈림** 감소 |
| **SC3** | meter↔feet↔yard 및 **입력 검증**(음수·형식·없는 단위)이 **테스트로 통과**해, 제출 전 **재계산·재확인**이 필요 없다 | ③ "**과제지연**" → **확인·지연 비용** 감소 |

---

## 8. 이번 프로젝트에서 하지 않을 것

| 하지 않을 것 | 이유 (Mom Test) |
|--------------|-----------------|
| **앱·UI·검색 기능**을 먼저 만드는 것 | 진짜 pain은 "프로그램 부재"가 아니라 **매번 찾기·확인·지연** |
| **모든 단위·공식 암기**를 전제로 하는 것 | "외우기 힘들다"가 반복 증거 — 암기 대신 **일관된 변환 규칙**에 위임 |
| **JSON/CSV/출력 포맷 선택** 등 부가 기능을 SC1~3 전에 우선 | 추가 요구이나, 이번 세션 핵심은 **즉시·정확·재사용** |
| **"만들면 좋겠다" 수준의 가설 검증 없이** 기능만 늘리는 것 | Mom Test 미검증 항목(지연 시간·감점 등)은 **범위 밖**으로 명시 |

## 9. 인터뷰 타임라인 요약

| 단계 | 질문 요지 | 핵심 답변 |
|------|-----------|-----------|
| Q1 | ft→m 변환 경험 | 코딩 수업, 교수님 지시로 변환 수행 |
| 추궁 | 불편한 순간 | 공식을 외우지 않아 방법을 찾아봄 |
| 추궁 | 찾기 전 걱정 | 단위 외우기 어려움, 다른 단위도 물어볼까 걱정 |
| Q2 | 다른 단위 실제 발생? | ft→m 성공 후, 다른 단위 숙지 지시 |
| Q3 | 이후 다른 단위 필요? | yard→ft 헷갈림 |
| 추궁 | 어떻게 끝났나 | 검색으로 해결 (솔루션 — 별도 기록) |
| 추궁 | 검색 직전 불편 | 새 단위마다 찾아봐야 함 |
| Q4 | 처음부터 그랬나 | 처음(ft→m)부터 |
| Q5 | 미리 준비했나 | 안 함 — 어떤 단위가 나올지 모름, 종류가 많음 |
| Q6 | 실제 손해 | 바로 답 못함, 매번 직접 찾아봐야 함 |
| 추궁 | 구체적 손해 | 과제 지연 |

## 10. 시사점

- **Pain은 "변환 자체"가 아니라 "매번 처음부터 찾는 반복"**에 있음.
- **불확실성**(다음에 어떤 단위?) 때문에 **사전 암기·준비가 실패**함.
- **과제 지연**까지 이어져, 단순 불편을 넘는 **시간 비용**이 확인됨.
- 아직 미확인: 감점·마감 초과·동기 수업 외 반복 여부 (Q7 미응답).

- **같은 수업 동기**도 같은 패턴인지 (3인 인터뷰)
